// ARCHITECTURE PRINCIPLES

Designing for
machine-led communication

Agents now call tools, tools call systems, and systems call other agents, often with no human in the middle. Architecture has to account for that. The first question for every team is which part it owns.

Principle: every team picks a role, and no automation ships alone.

How to read it: machines talk to machines at the top. Underneath, every capability they call comes from one of three contributor roles, and all of it runs on a single operations layer. The right-hand column shows who delivers each layer: domain teams create the context, Forward Deployed Engineers build with them, and Infra & Ops host the result. Humans stay accountable for the outcome.

// PART 1 · FOUR ROLES

Pick your role in the machine economy

Three ways to contribute and one way to keep it all running. A team can play more than one role, but it should know which one it's playing.

Contribute
🛠️
01 · BUILDER
Automate the edges
Solve the long tail.

Build the edge automation, the team-specific workflows a central platform will never get to.

  • Start where the manual hours are.
  • Compose shared connectors. Don't write private glue.
  • Promote what spreads; retire what doesn't.
Rule: build on the shared layer, not around it
🔌
02 · CAPABILITY DEVELOPER
Build the connector
Make your system callable.

Turn a system or skill into a governed, reusable capability (an API or MCP connector) that any agent can discover and use.

  • Clear contract: inputs, outputs, errors.
  • Auth, rate limits and audit built in.
  • Versioned, so consumers don't break.
Rule: one connector, many consumers
📊
03 · DATA PROVIDER
Be the source of truth
Publish data machines can trust.

Provide clean, documented, timely data with a named owner, so automation can act on it without a person double-checking.

  • Defined schema and freshness.
  • Quality checks before publishing.
  • Lineage that explains every number.
Rule: if machines can't trust it, they can't act on it
Operate
🛰️
04 · OPERATOR
Keep it running
Automation is only as good as its uptime.

Run what the other three roles produce: monitor it, secure it, pay for it, and answer for it when it breaks.

  • Monitoring and alerting on every agent and connector.
  • Access control, audit trail and kill switch.
  • Cost and capacity tracking.
  • Incident ownership with a human on call.
Rule: every automation has an owner on call
